> 需求见 [PRODUCT-REQUIREMENTS.md](../../PRODUCT-REQUIREMENTS.md)「第十轮」与 [REQUIREMENTS-CONSOLIDATED.md](REQUIREMENTS-CONSOLIDATED.md) 第 9 节（R-9.1–R-9.9）。

## 1. bot 是什么

bot 是一个稳定身份，和 provider 会话分开。换模型、换 provider、重开会话都不改变 bot 的 id、历史入口、记忆和例程。

| 字段        | 说明                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------- | ----------- |
| `id`        | 稳定 id，`bot_` 前缀                                                                         |
| `kind`      | `independent`（独立 bot，界面叫「bot」）或 `project`（项目 bot）                             |
| `projectId` | 项目 bot 必填，独立 bot 为空                                                                 |
| 身份        | 名字、头衔、头像（自有生成：seed + 色相；或自定义图片 ≤512 KB）、角色说明                    |
| 运行        | 预设或 provider/模型/思考强度、备用模型链（沿用现有预设语义 R-4.1）、通知开关                |
| 会话        | 主对话一个 Paseo agent；旁线程各一个 Paseo agent，都带 `vibe.bot=<id>`、`vibe.bot-thread=<id | main>` 标签 |

工作目录：项目 bot 为项目仓库根；独立 bot 为 `$VIBE_HOME/bots/<id>`。

### 职责

- **独立 bot** 可以开多个，是 openbot 那样的通用长期队友：不属于任何项目，没有预设职责，做什么由你写的角色说明决定（2026-10-29 用户更正）。它可以用跨项目工具：查看各项目与任务、给项目开任务、查看和调整调度队列；这些是可用工具，不是固定角色。
- bot 都不自动派发。跨项目排队派发只由调度器规则执行，原「派发开关打开时由总 agent 决定排序」取消。
- **项目 bot** 每个项目可以开多个，都能接需求、新开或续接任务（R-2.3）、维护项目简介（R-2.4/2.5）。项目设置里选一个「默认项目 bot」，环境故障通知（R-2.7）和任务完成后的需求整理交给它。
- 现有数据迁移：vibe-master 的总 agent 变成第一个独立 bot；每个项目已有的项目 agent 变成该项目的默认项目 bot。保留原会话，不丢历史。

## 2. bot 能力

| 能力         | 做法                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 对话式自配置 | MCP 工具 `vibe_bot_read`、`vibe_bot_update`（名字/头衔/说明/头像/模型/思考强度/备用模型/通知）、`vibe_models_list`、`vibe_bot_create`。校验与设置页相同。模型变更在 bot 空闲时生效：同 provider 用宿主 `setAgentModel`；换 provider 开新会话并带交接包（R-3.11）。bot 只能收紧自己的权限，不能放宽。                                                                                                                                                                                                                                               |
| 长期记忆     | vibe.db 表 `bot_memory`（文本、置顶、来源、更新时间）。工具 `vibe_memory_add/update/remove/list`。主对话创建及换 provider 重建时，以 4000 字符预算写入系统提示（置顶优先，其余最近更新优先，超出截断标注），保存已送达快照版本。后续仅在版本变化时，于实际 provider turn 前以 user-role 附系统围栏上下文，只含新增/修改/删除差异；无变化不附加。provider 接受回合后确认版本，发送失败可重试。系统块不构成用户执行授权（R-3.9）。资料面板里可查看、编辑、删除。项目 bot 共用 AGENTS.md/CLAUDE.md 作项目记忆，个人记忆只放偏好与经验。手机离线可读。 |
| 定时例程     | vibe.db 表 `bot_routines`（cron 或间隔、时区、提示词、目标：主对话/新旁线程、静默、暂停、错过运行策略）。由调度器触发，受资源准入（R-5.3）约束。失败推送通知、侧栏 bot 头像上显示红叉。列表与周历视图。现有维护规则作为「系统例程」出现在同一列表和日历里，数据和「先出方案再执行」（R-6.2）不变。                                                                                                                                                                                                                                                 |
| 旁线程       | 同一 bot 下并行话题，每个是独立 Paseo agent，共享 bot 身份、记忆和工作目录。对话头部显示旁线程 tabs，可新建、改名、归档。上限 8 个未归档。旁线程不是任务，任务仍走独立 worktree + #1–#6。                                                                                                                                                                                                                                                                                                                                                          |
| 可视化回复   | 工具 `vibe_html_render(title, html, height)`，存为 `text/html` 附件并在时间线插入卡片。Web/Electron 用 `sandbox="allow-scripts"` 的 iframe（无 same-origin），Android 用 WebView 并禁用文件与跨源访问。页面只能经白名单消息与宿主交互：高度、主题、点击后把文字放进草稿。                                                                                                                                                                                                                                                                          |

## 2.5 流程档位（第十轮第 6 条）

| 档位 | 用到的 tab                                   | 授权                                                         | 验证                                   |
| ---- | -------------------------------------------- | ------------------------------------------------------------ | -------------------------------------- |
| 简单 | #1（评估 + 简短方案）、#4                    | 用户新建时亲自选简单即授权；bot 自动定的简单要点一次「执行」 | #4 自测（typecheck/lint/相关测试）留证 |
| 中等 | #1、#2（单模型，不互审）、#4、#6；#3/#5 按需 | 用户确认方案                                                 | #6 独立验证                            |
| 完整 | #1–#6，#2 多模型互审                         | 用户确认方案                                                 | #5 复核 + #6 验证                      |

任务记录保存 `flow_level`、`flow_source`（`user` / `bot`）和 `flow_reason`；旧任务默认完整。项目 bot 依据预计改动范围、模块、风险、可回退性及现成测试评估新任务，并提供档位和理由。迁移、协议、删数据、权限及发布类任务最低中等：服务端将违规的简单档升为中等，并在 #1 说明。

新建任务可选自动、简单、中等或完整，默认自动。用户可在 #1 输入 `/流程 简单|中等|完整` 或在流程面板改档；各 tab 可向 #1 建议升档，由用户确认。固定显示 #1–#6，当前档位未启用的 tab 用占位状态标记「本流程未启用」，点击可单独启用；未启用时不创建 agent。

简单档由 #4 在交付中提供 typecheck、lint 和相关测试命令；回合结束后宿主获取调度器全仓验证写屏障，运行命令并保存实际输出，前后检查干净 HEAD。命令失败或代码发生变化时验证不通过。查看流程面板或验收时再次比对代码并使过期证据作废；没有后台文件监听。调度器重启后冻结已有屏障并暂停，避免把中断的验证当作成功。验证须绑定当前代码快照，不能用执行者的文字报告替代受控证据。三档共用调度、文件锁和 Git 收尾规则。

## 3. 界面

### 3.1 视觉基础

照 openbot 的令牌体系在 RN 里建自己的主题（深色默认，浅色可选）：

- 语义色：画布、外框、侧栏、表面、控件、边线、文字四档、强调蓝、成功/警告/危险及其淡底。
- 字号六档：12/16、13/18、14/20、16/22、18/24、24/30。
- 间距：2/4/6/8/12/16/24/32。圆角：4/6/8/12/14/20/999。
- 控件高度：24/28/32/36/40。动效 120–240 ms，遵守减少动态效果设置。

具体数值以拆解报告第 1 节为准，写进 `packages/app` 的主题文件，替换现有 Paseo 令牌。组件统一走一层自有原语：Button、IconButton、Input、Switch、Menu、Dialog、Sheet、Tooltip、ListRow、Avatar、Badge。图标继续用 lucide。

### 3.2 桌面布局

```text
┌52 页面轨┬ 280 侧栏（可调 128–400，可折叠到 88） ┬ 对话主区 ┬ 右面板 360 ┐
│ bot     │ 主机 ▾                       [+]     │ 身份与对话 │ 资料/流程  │
│ 例程    │ 搜索                                 │           │            │
│ 提示词  │ [项目] [日期] [状态]                 │ 消息流    │            │
│ 调度器  │ ▾ 独立 bot                           │           │            │
│ 用量    │   ◉ bot 名称                         │           │            │
│         │ ▾ 项目名                         [+] │           │            │
│         │   ◉ 默认 bot                         │           │            │
│         │   ▣ 任务名称                         │ composer  │            │
│ 设置    │ ▾ 其他                               │           │            │
└─────────┴──────────────────────────────────────┴───────────┴────────────┘
```

- 页面轨顺序：bot、例程、提示词仓库、调度器、用量，设置在底部（2026-10-29 用户拍板，取代第九轮「主侧边栏顶部 总 agent → 提示词仓库 → 调度器」）。手机上这些入口在抽屉顶部。
- 额度圆环：设置之上的一组，每个有窗口限额的订阅账号一个 36 圆环，外圈为最长窗口、内圈为次长窗口，弧长是剩余量。剩余 30% 以上绿、10–30% 橙、10% 以下红。悬停出用量卡，点击打开用量页并把该账号排到最前。数据超过 5 分钟才重拉，页面隐藏时不拉。手机抽屉顶部只画剩余最少的两个，其余显示 +N。悬停卡没有 250 ms 的延迟，立即出现。模型在 `packages/app/src/usage/rings.ts`，界面在 `rings-view.tsx`。
- 侧栏顶部以紧凑分段按钮切换「项目」「日期」「状态」，每台主机在本地记住选择，默认按项目。列表左右留 12，空组不显示。
- 按项目时，独立 bot 单独成组并置顶；每个项目下平铺 bot 和任务，默认项目 bot 排第一，其余按最近活动排列。项目组可折叠，组头的新建菜单提供新任务和新项目 bot。无项目的普通会话放「其他」。
- 按日期以本地日期分为今天、昨天、最近 7 天、更早；按状态分为需要你、运行中、空闲及其余。各组平铺条目，日期分组的副文字显示项目名。
- 条目使用统一行：头像、名称、可选单行副文字及状态或未读提示。bot 使用自有圆形头像，任务使用带任务图标或序号的圆角方形头像，普通会话使用中性图标。保留选中态和行菜单；桌面悬停显示菜单，原生端常显。
- 选中 bot：头部是头像、名字、头衔，右侧模型选择和资料面板开关。资料面板（WP-154）按 openbot 排版，桌面右侧抽屉 360 宽，手机全高 sheet 共用同一套行组件（`plugins/vibe-bots/client/settings-kit.tsx`）：根页自上而下是头像（点开选颜色）、名字、头衔、角色说明（固定 120 高）、模型卡（统一模型选择器，`model-section.tsx`；旧 bot 的预设已由迁移展开成 bot 自己的模型字段；仍引用角色设置的显示一行说明，重新选择后不再引用）、备用模型入口、记忆与例程入口、规则卡（权限、通知、高级）。备用模型、记忆、例程、权限、通知、高级是带 39 高头部和返回键的子页。全部即时保存、无保存按钮：名字/头衔失焦保存，说明停止输入 400ms 后保存，其余先乐观更新 bot 列表缓存再串行发送，失败回滚并在页底显示错误（`use-bot-saver.ts`）；只有放宽权限会弹确认，归档在「高级」里的 outline 按钮加确认。打开面板直接用已缓存的 bot 列表，后台再刷新。头像图片上传暂未做（宿主还没有给插件的文件选择能力）。非 git 目录（独立 bot）打开右侧栏时落在「文件」而不是「更改」。
- 选中任务：头部保留「项目 / 任务名」与分支，固定六个流程 tab 使用单行短标题、状态图标和紧凑控件；模型与状态详情放在悬停提示或原生长按菜单中。未启用档位降低不透明度，点击仍可启用。空间不足时横向滚动，边缘渐隐提示更多内容，选中项自动滚入；Web 支持滚轮、触控板和鼠标拖动，Android 支持手指滑动。右侧流程面板保留进度、子任务、其他方案、证据和执行/通过/停止，角色行精简为编号、角色与状态。
- composer：容器、附件、引用、提示词书本按钮照 openbot 样式重画；保留「发给 #n」、slash 命令、outbox 与离线首消息。

### 3.2.1 模型选择器（WP-150、WP-177、WP-182）

全应用只有这一个模型选择器，实现在 `packages/app/src/components/provider-model-picker/`：composer、bot/普通会话顶行（同一个 `AgentControls`，窄屏也走它，选择器自己变底部 sheet）、新建任务、调度表单、元数据生成设置、插件的 `ModelPickerField`（bot 资料、新建 bot、任务角色）都用它。预设（agent 配置）已改称角色设置并并入「任务角色」页，不再出现在任何选择处；旧的 `model-browser`、`CompactModelSheet`、预设管理页已删除。`combined-model-selector.tsx` 只是把旧参数转给它的适配层。

- 结构：左 52 宽 provider 竖栏 + 右面板（标题和副标题、不可用时的状态块和重试、搜索、按服务分组的模型列表，底部依次是推理强度、快速、权限三行）。只有一个 provider 时不画竖栏。竖栏项悬停显示左侧 tooltip。
- 触发器：28 高 pill，`provider 图标 · 模型名 · ⚡ 快速（开启时）· 推理强度 ⌄`；通过 `renderTrigger` 可换成整行表单触发器，此时弹层宽度等于触发器宽度。
- 弹层定位（`placement.ts`，纯函数有单测）：默认触发器下方右对齐、间距 8、宽 min(360, 视口-24)；下方放不下且上方更宽松时翻到上方；横向贴边（距边 8）；最大高 min(520, 视口-100, 所在一侧剩余空间)，最小高 226；只有模型列表滚动，标题、搜索、强度行不收缩。触发器测量完成前不挂载弹层。web 渲染到 overlay-root，原生用 Modal；窄屏改用底部 sheet。
- 响应：点开立即显示，列表用缓存快照，后台刷新就地更新；选中后按钮立刻显示新值（`use-optimistic-selection.ts`），请求在后台发出，抛错或 promise 拒绝时回滚并 toast。
- 键盘（web）：↑↓ 环绕移动高亮，Enter 选中，Esc 关闭。选中后没有强度行也没有快速行就自动关闭。
- 推理强度：一律用分段控件，档位多时横向紧凑排列并可横向滚动，不再退成下拉（选中段背后的 pill 用文字色 12% 底加顶部 1px 高光，250ms 滑动，首次放置与 resize 不动画，整体禁用 0.5 透明）。标签中文化为 低/中/高/极高/最高（`localizeEffortLabel`）。
- 快速：provider 带快速功能就显示开关，工具栏上没有单独的快速按钮。Claude 是 `fast_mode` 开关；Codex 的速度是 `service_tier` 选择（`default`/`fast`），选择器把它折成同一个开关（`picker-controls.ts` 的 `findFastControl`，有单测）。该功能由 daemon 按当前模型给出，模型不支持时不显示。插件的 `ModelPickerField` 通过 `fast`/`onFastChange` 接入（角色设置已接，bot 没有快速字段，未接）。
- 权限：面板最底一行，同样的分段控件，选中即生效，标签中文化（Claude：计划/每次询问/接受编辑/自动/完全放行；Codex：默认/自动/完全访问）。运行中的 agent 走 `setAgentMode`，工具栏上不再有模式按钮（循环切换快捷键随之失效，命令中心里仍可切换，计划模式也只在命令中心）。新会话、角色设置、bot 默认权限一律是「自动」档：Claude 的 `auto`，Codex 的 `auto-review`（`presetModeId`，注意 Codex 自己的 `auto` 只是默认审批流）。插件的 `ModelPickerField` 用 `permission`/`onPermissionChange`（`accept-edits`/`auto`/`full` 三档），新建 bot 表单默认自动；bot 契约和数据库的默认值仍是 `accept-edits`（bot 创建 bot 时只能收紧权限，改默认值会让它们建不出来）。
- 切换服务商：运行中会话在选择器里选另一家模型时，bot 会话调 vibe-bots `bots.update`（空闲后生效），其余会话调 switch-provider 的 `session.switch` 开新会话并带交接内容，然后打开新会话；本轮还在跑时提示「本轮结束后切换」，回合结束后执行。
- 「下轮生效」：agent 运行中，配置的模型或强度与运行时不同，顶行选择器左侧显示徽标（`next-turn.ts`，有单测）。
- 未做（对照 openbot 规格）：免费档排序、多账号 tab、「+ 添加 provider」入口、触发器文字切换动画、列表上下渐隐、rail 的方向键循环。

### 3.3 Android

抽屉（页面轨入口 + 同样的分组按钮和列表）→ 对话页 → 资料/流程用全高 sheet。设置逐层子页。离线 outbox 的待发状态显示在对应消息上。功能与桌面一致（R-8.3）。

### 3.4 设置

桌面：左分类导航 + 右正文（内容最大宽 784），分类内用分组卡，行最小 64 高。插件设置页直接列在分类里（WP-136）。长文档、简介等一律子页面。原生项目自动关联任务项目扩展；「任务角色」配置角色及方案审阅者超时。bot 资料和记忆在会话右侧资料面板管理，在总协调 bot 会话右侧常驻的「自动维护」面板管理规则，不再单列设置页。模型列表刷新入口位于统一模型选择器内。切换设置项时导航列表保持当前滚动位置。
