## 1. bot 是什么

bot 是一个稳定身份，和 provider 会话分开。换模型、换 provider、重开会话都不改变 bot 的 id、历史入口、记忆和例程。

| 字段        | 说明                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------- | ----------- |
| `id`        | 稳定 id，`bot_` 前缀                                                                         |
| `kind`      | `independent`（独立 bot，界面叫「bot」）或 `project`（项目 bot）                             |
| `projectId` | 项目 bot 必填，独立 bot 为空                                                                 |
| 身份        | 名字、头衔、头像（自有生成：seed + 色相；或自定义图片 ≤512 KB）、角色说明                    |
| 运行        | 预设或 provider/模型/思考强度、备用模型链（沿用现有预设语义 R-4.1）、通知开关                |
| 会话        | 主对话一个 Paseo agent；旁线程各一个 Paseo agent，都带 `vibe.bot=<id>`、`vibe.bot-thread=<id | main>` 标签 |

工作目录：项目 bot 为项目仓库根；独立 bot 为 `$VIBE_HOME/bots/<id>`。

### 职责

- **独立 bot** 可以开多个，是 openbot 那样的通用长期队友：不属于任何项目，没有预设职责，做什么由你写的角色说明决定（2026-10-29 用户更正）。它可以用跨项目工具：查看各项目与任务、给项目开任务、查看和调整调度队列；这些是可用工具，不是固定角色。
- bot 都不自动派发。跨项目排队派发只由调度器规则执行，原「派发开关打开时由总 agent 决定排序」取消。
- **项目 bot** 每个项目可以开多个，都能接需求、新开或续接任务（R-2.3）、维护项目简介（R-2.4/2.5）。项目设置里选一个「默认项目 bot」，环境故障通知（R-2.7）和任务完成后的需求整理交给它。
- 现有数据迁移：vibe-master 的总 agent 变成第一个独立 bot；每个项目已有的项目 agent 变成该项目的默认项目 bot。保留原会话，不丢历史。

## 2. bot 能力

| 能力         | 做法                                                                                                                                                                                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 对话式自配置 | MCP 工具 `vibe_bot_read`、`vibe_bot_update`（名字/头衔/说明/头像/模型/思考强度/备用模型/通知）、`vibe_models_list`、`vibe_bot_create`。校验与设置页相同。模型变更在 bot 空闲时生效：同 provider 用宿主 `setAgentModel`；换 provider 开新会话并带交接包（R-3.11）。bot 只能收紧自己的权限，不能放宽。 |
| 长期记忆     | vibe.db 表 `bot_memories`（文本、置顶、来源、更新时间）。工具 `vibe_memory_add/update/remove/list`。每回合按预算注入（置顶优先，其余按最近）。资料面板里可查看、编辑、删除。项目 bot 共用 AGENTS.md/CLAUDE.md 作项目记忆，个人记忆只放偏好与经验。手机离线可读。                                     |
| 定时例程     | vibe.db 表 `bot_routines`（cron 或间隔、时区、提示词、目标：主对话/新旁线程、静默、暂停、错过运行策略）。由调度器触发，受资源准入（R-5.3）约束。失败推送通知、侧栏 bot 头像上显示红叉。列表与周历视图。现有维护规则作为「系统例程」出现在同一列表和日历里，数据和「先出方案再执行」（R-6.2）不变。   |
| 旁线程       | 同一 bot 下并行话题，每个是独立 Paseo agent，共享 bot 身份、记忆和工作目录。对话头部显示旁线程 tabs，可新建、改名、归档。上限 8 个未归档。旁线程不是任务，任务仍走独立 worktree + #1–#6。                                                                                                            |
| 可视化回复   | 工具 `vibe_html_render(title, html, height)`，存为 `text/html` 附件并在时间线插入卡片。Web/Electron 用 `sandbox="allow-scripts"` 的 iframe（无 same-origin），Android 用 WebView 并禁用文件与跨源访问。页面只能经白名单消息与宿主交互：高度、主题、点击后把文字放进草稿。                            |

## 3. 界面

### 3.1 视觉基础

照 openbot 的令牌体系在 RN 里建自己的主题（深色默认，浅色可选）：

- 语义色：画布、外框、侧栏、表面、控件、边线、文字四档、强调蓝、成功/警告/危险及其淡底。
- 字号六档：12/16、13/18、14/20、16/22、18/24、24/30。
- 间距：2/4/6/8/12/16/24/32。圆角：4/6/8/12/14/20/999。
- 控件高度：24/28/32/36/40。动效 120–240 ms，遵守减少动态效果设置。

具体数值以拆解报告第 1 节为准，写进 `packages/app` 的主题文件，替换现有 Paseo 令牌。组件统一走一层自有原语：Button、IconButton、Input、Switch、Menu、Dialog、Sheet、Tooltip、ListRow、Avatar、Badge。图标继续用 lucide。

### 3.2 桌面布局

```text
┌52 页面轨┬ 280 侧栏（可调 128–400，可折叠到 88） ┬ 对话主区                    ┬ 右面板 360 ┐
│ bot     │ 主机 ▾                       [+]     │ 头像 名字 · 旁线程 tabs  模型 ▾ 面板 │ 38 高顶行 │
│ 例程    │ 搜索                                 ├─────────────────────────────┼───────────┤
│ 提示词  │ bot                          [+]     │ 消息流（最大宽 1440 居中）   │ 资料/流程 │
│ 调度器  │  ◉ 总调度   头衔   状态               │                             │ 文件等    │
│ 用量    │ 项目                                 │                             │           │
│         │  ▾ myVibeBoard           [⋯]         │                             │           │
│         │     项目 bot              [+]        │                             │           │
│         │      ◉ 产品 bot  状态                │                             │           │
│         │     任务                  [+]        │                             │           │
│         │      ▸ 重做界面  执行中              │ composer                    │           │
│ 设置    │     其他会话（折叠）                 │                             │           │
└─────────┴──────────────────────────────────────┴─────────────────────────────┴───────────┘
```

- 页面轨顺序：bot、例程、提示词仓库、调度器、用量，设置在底部（2026-10-29 用户拍板，取代第九轮「主侧边栏顶部 总 agent → 提示词仓库 → 调度器」）。手机上这些入口在抽屉顶部。
- 侧栏行：bot 行 54 高、头像 36；状态用不同图形区分工作中、已回复、未读计数、例程运行、等待你（审批/提问）、失败。任务行显示阶段与等待原因。
- 普通 workspace（非任务）放在项目下「其他会话」里，不补 #1–#6。
- 选中 bot：头部是头像、名字、头衔，右侧模型选择和资料面板开关。资料面板分身份、模型与备用、说明、通知、记忆、例程，长内容进子页。
- 选中任务：头部是「项目 / 任务名」、分支，下面一条固定流程条 `#1 主会话 | #2 方案 | #3 探路 | #4 执行 | #5 复核 | #6 验证`（WP-136 的占位 tab 规则照旧），右面板是流程面板（进度、子任务、其他方案、证据、执行/通过/停止）。
- composer：容器、附件、引用、提示词书本按钮照 openbot 样式重画；保留「发给 #n」、slash 命令、outbox 与离线首消息。

### 3.3 Android

抽屉（页面轨入口 + 侧栏树）→ 对话页 → 资料/流程用全高 sheet。设置逐层子页。离线 outbox 的待发状态显示在对应消息上。功能与桌面一致（R-8.3）。

### 3.4 设置

桌面：左分类导航 + 右正文（内容最大宽 784），分类内用分组卡，行最小 64 高。插件设置页直接列在分类里（WP-136）。长文档、简介等一律子页面。
