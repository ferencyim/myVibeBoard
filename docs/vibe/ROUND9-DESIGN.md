# 第九轮设计：离线首消息、项目 agent 与环境排查

> WP-133、WP-134，2026-10-28。需求见 [PRODUCT-REQUIREMENTS.md](../../PRODUCT-REQUIREMENTS.md)「第九轮修正」。任务仍使用第八轮的原生多 tab；离线数据由宿主持久缓存承载，不恢复离线插件运行。

## 离线首消息

模型选择器提供「默认模型（联网后按项目设置）」，离线新建时默认选中。首消息 outbox 保存默认选择的意图，不在离线时冻结某个模型；联网发送前按任务、项目、全局顺序解析 #1 主会话，均未配置时按主机返回顺序选择第一个已启用且 ready 的 provider，省略 model，让 daemon 使用该 provider 的默认模型。没有可用 provider 时保留队列并等待后续重试。显式选定模型则保留该选择。

现有创建协议要求 provider 必填，没有跨 provider 的默认配置。上述选择是本次实现对需求中“默认 provider”的具体解释，已向用户展示选项；尚未收到回复时按推荐项完成可逆实现。

默认解析必须发生在创建请求前，使用现有 first-message 幂等键和回执查询。请求结果未知时先核对回执，不能因默认配置变化创建第二个任务。附件、正文与本机状态仍复用原生首消息 outbox，不允许后续消息或执行授权离线入队。

每台主机缓存最后一次成功获取的 provider/模型快照，使用 app 现有持久存储并按 serverId 隔离。离线展示缓存及「上次同步」时间；没有缓存时仍可保存默认模型首消息。项目、分支、预设与提示词插入沿用已有缓存边界；无法从本机恢复的数据必须显示具体原因，不伪造选项或成功状态。

## 默认模型设置

设置新增独立「任务默认模型」页，项目设置的 worktree scripts 同页增加同名一节。项目覆盖全局；项目未覆盖项显示「沿用全局：xxx」。所有读写复用现有 vibe.db 默认模型与预设命令，不建立另一份设置。

| 设置             | 语义                               |
| ---------------- | ---------------------------------- |
| #1 主会话        | 首消息默认模型                     |
| 项目 agent       | 角色 project，项目 agent 使用      |
| #2 方案          | 有序预设列表，第一个写作，其余审阅 |
| #3 探路、#5 复核 | 预设、沿用 #1 或显式不启用         |
| #4 执行、#6 验证 | 预设或沿用 #1                      |

角色未配置保留 WP-132 的 main-fallback，不能解释为关闭；只允许探路与复核显式关闭。预设管理保留，旧弹窗的默认模型入口跳转到新页面，避免两处编辑逻辑。表单遵守 [forms.md](../forms.md)，使用纯 TypeScript 状态模型及宿主表单、设置控件，手机和桌面共享内容。

## 项目 agent

每个原生项目按需创建一个长期项目 agent，会话归档后下次打开重建，工作目录固定为项目仓库根。侧边栏项目分组第一行是固定入口，桌面与手机共享。模型按项目 project 角色、全局 project 角色、最近任务 #1、主机第一个可用 provider 解析，沿用 WP-133 的 provider 默认模型语义。

项目 agent 接收需求，参考同项目任务、目标、阶段和方案状态，决定新建任务或续接；无法判断时询问用户。新任务复用普通任务创建链路建立 #1–#6（保留显式关闭可选角色的规则），需求作为 #1 首消息，工作区与首消息都使用原消息 ID 去重。续接只转发已由宿主用户输入钩子核实的原话，状态行链接到目标 #1。工具调用本身不构成用户授权；诊断、任务完成通知和 agent 消息不能进入用户身份投递路径。真实输入凭据持久化在 daemon 私有元数据中，每会话最多 20 条、8 MiB，供澄清后及重启后继续路由；超限时提示重发，不截断后冒充原话。项目 agent 不写方案、不改业务代码、不替用户确认方案或批准工具。

任务完成后的本项目记忆与需求整理迁给项目 agent；总 agent 只决定跨项目已确认任务的派发顺序。整理提示词、完成触发和开关一并迁移，避免两边重复处理。项目 agent 的默认角色提示词进入提示词仓库，沿用全局与项目覆盖。

AGENTS.md 与 CLAUDE.md 是项目简介和兼容不同 agent 的记忆真相源；简介显示文件快照和同步时间。daemon 每 15 秒轮询这两份文件、PRODUCT-REQUIREMENTS.md 与 docs/ 下 Markdown，缓存内容到 vibe.db，经现有插件 RPC 通道供手机使用。每份文件最多读取前 64 KiB，避免为简介引入新的核心递归 watcher 接口；大目录仍有枚举成本，变化不会即时推送。大文件只保留有大小标识的截断快照，不能将截断内容当完整文件覆盖。符号链接不能越过项目根。

项目设置的「项目简介」与「项目文档」使用共享 Markdown 引擎。宿主保留持久缓存，使断网及离线冷启动也能阅读。简介编辑保存为待合并修改；重连后带来源说明交给项目 agent，合并写回真相源并明确确认完成后才清除对应修改。新编辑不能被前一次合并回执清掉。文档只读。项目设置和简介写入不能记录密钥、主机地址、用户名。

项目配置优先复用现有项目配置存储和 API，工具只能修改调用项目的设置。项目专用工具在 daemon 侧校验会话角色标签和所属项目；任务 tab 调用必须拒绝。

## 环境故障自主排查

检测在 daemon 的时间线与状态事件上进行，涵盖执行进程创建前失败、沙箱初始化错误、provider 模型满载或不可用、agent 启动失败；不依赖故障会话执行诊断 shell。同一会话同类错误限频，通知带任务、tab、原始错误、时间、provider 和模型上下文。

项目 agent 通过只读诊断工具查看近期错误、相关日志、provider 就绪状态及相关进程是否存在和 CPU。恢复工具限制在同项目任务 tab：重试、依预设候选顺序换模型、重开 tab，并保留上下文和任务绑定。更改系统设置、提升权限、结束他人进程只能建议，由用户决定。

项目 agent 自身故障时追加可见状态行并在项目入口显示异常，不能递归唤醒自身。故障诊断和完成整理通知始终是系统来源，不能消费用户原话转发授权。

## 最小核心扩展

插件通过 client.addProjectSettingsSection 注册项目设置内容。宿主负责标题、排序、项目和主机上下文，以及插件运行时与错误边界；插件负责自己的数据加载和保存。组件接收 projectId、serverId、theme、compact，不操作核心 worktree scripts 表单。

项目分组固定行通过 client.addProjectSidebarItem 注册，宿主负责主机归属、错误边界与统一 agent 导航。项目配置 SDK 只补出已有 readConfig/writeConfig RPC；可信用户成功投递事件是内部生命周期扩展，不新增 wire 消息。离线简介由宿主 UI 与持久缓存承载，不能依赖断线后插件仍运行。

通用 API 合同见 [plugins.md](../plugins.md#contribute-settings)。协议如需扩展仍遵守 [兼容约定](../protocol-compatibility.md)；本机 outbox 的默认选择标记不作为新的必填 wire 字段。

## 验证与经验

验收覆盖无模型缓存离线保存、默认解析与显式选择、按主机缓存读写、设置覆盖/回退、扩展点注册/排序。仅运行改动测试文件及受影响包类型检查、定向 lint 和格式化；真实 Android 飞行模式与设备重启效果须另有设备证据。

持久缓存已有工作目录维度时，应保留该维度并补主机最近成功快照的回退，避免把另一个项目的即时能力误当在线结果。跨包声明的联接可能指向其它检出，验证只构建本 worktree，必要时用临时类型映射，不能改共享检出。映射客户端时须按 package exports 对齐 internal 子路径，否则同名 DaemonClient 的私有字段会造成跨检出类型冲突。

项目 agent 普通用户消息不能由 before 钩子先接管，否则模型没有机会决定新开还是续接；成功投递后的内部事件才提供完整原话与附件。离线简介同步必须由宿主后台重连触发，不能只放在设置组件挂载期间。
