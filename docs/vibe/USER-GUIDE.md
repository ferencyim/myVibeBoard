# myVibeBoard 使用指南

myVibeBoard 在 Paseo 的原生 workspace 和会话里协作。一个任务对应一个独立 Git worktree 和一个会话 tab；规划、探路、执行、复核、验证的公开发言都留在这条会话中。侧栏 workspace 列表就是任务列表。

第五轮已实现原生任务流程与旧看板切换。本次发布的实测范围、截图和未测项以 WP-114 验收报告为准。构建、模型登录和连接分别见 [BUILD.md](BUILD.md)、[AGENTS-SETUP.md](AGENTS-SETUP.md)、[CONNECTIVITY.md](CONNECTIVITY.md)。

## 开始前

daemon 启用插件后，安装 `vibe-board`、`vibe-context`、`vibe-master`、`vibe-scheduler`、`vibe-maintain`、`vibe-stats`、`vibe-verify`。`vibe-board` 名称保留用于兼容插件身份，现在提供任务面板、模型预设与 Agent 行为设置。插件应与本 fork 的宿主一起升级；不要只替换其中一个包。

先到「任务设置 → 管理项目与 Agent 预设」建立项目扩展，关联原生 Paseo 项目，核对主仓库路径和项目类型。证据验证需要这份配置；未关联会暂停并提示，不能靠模型猜建项目。

在同一管理页配置预设及七个角色的默认模型：探路、规划、方案复核、执行主代理、子代理、代码复核、验证。「Agent 行为」负责提示词与自动化设置。项目默认覆盖全局默认；任务面板还能在确认前选择本次角色。探路、方案复核、代码复核可以不启用，规划、主代理、验证必须可用，子代理未选时沿用主代理。预设内模型按顺序失败接续，候选耗尽时显示原因，不会悄悄把任务当成成功。

## 新建任务并讨论方案

1. 在原生项目下新建 workspace，选择独立 worktree，在输入框写需求并附上参考文件或图片。首消息就是任务输入，不用另外填标题、描述、验收表单。
2. 规划模型在同一会话回复，可以先问清需求。你继续在输入框补充限制、回答问题或要求修改。
3. 打开会话内任务面板，点「制定方案」。启用探路时，探路成员先只读检查，再由规划成员写完整方案；面板保存目标、方法、文件范围、子任务及逐条验收条件。
4. 需要第二意见时选择方案复核模型并点「复核方案」。意见在会话里公开，再交回规划成员修改。可以反复进行。

规划与探路均只读。普通的「认可」「确认」「可以」和切换模型都不会授权修改代码。确认前请在面板核对最新方案；不完整或仍在输出的方案不能执行。

## 执行、复核、验证与通过

点面板「执行」或输入 `/执行`，才会保存最新完整方案、确认时间和角色快照，并交给调度器。执行只能使用任务自己的附加 worktree。资源不足、文件范围冲突或前置子任务未完成时显示排队原因。

主代理在当前会话接手，按方案委派子任务。子代理以可展开子会话呈现，共用本任务 worktree，计入并发限制；面板显示依赖、状态、实际模型和交付摘要。工具细节默认收起，待审批操作始终可见。审批发给提出请求的后台成员；只读成员只能提问，不能借审批取得写权限。

主代理交付后，启用了代码复核就先复核；所有任务都必须验证。复核或验证发现问题时，任务会退回修复或暂停，并显示原因。验证证据只对当前确认轮次和当前代码提交有效，不能沿用旧轮通过结论。你也可以在面板查看交付、复核、验证证据及历史。

验证会保存本轮 Git 提交、文件清单、工作树状态和差异原文。采集失败会存疑；临时工具描述不能代替已保存的证据文件。

验证完成后，点「通过」、输入 `/通过`，或在当前任务会话中单独发送「通过」。这会尝试安全合并到项目本地 `main` 并 push `origin main`。每次通过尝试都会留下记录；重试要发起新的操作。出现未提交修改、主检出脏树、代码已变化或冲突时停止并说明原因，不会强制覆盖。已经合并而 push 失败时保留待推送状态，排除网络或权限问题后再尝试。完成后 workspace、worktree、会话和沉淀都保留。

方案范围发生变化时，先停止旧执行，再修改方案并重新执行确认。不要用换模型或重新点击执行绕过尚未停止的写者。投递或停止结果不明时，按界面提示核对原成员。

## 任务面板与接手者

宽屏任务面板位于会话侧边；手机和窄屏展开为 sheet。面板集中显示当前阶段、阻塞原因、方案、探路结果、两类复核、子任务、交付、证据和 Git 收尾。制定方案、复核方案、执行、复核、验证、通过与对应 slash 使用相同流程。

输入框旁的「谁来接」选择后续接手角色、预设或模型。新成员会拿到已有公开上下文，旧发言仍显示原来的角色与实际模型。模型的私有推理不会迁移。确认后的角色快照不会因修改全局默认而改写；需要改方案时先停止并重新确认。

面板按成员最后请求时间和 provider 缓存时长估算到期倒计时。缓存未过期时换模型会提示额外 token 成本。到期前可点「压缩」，「到期前自动压缩」默认开启；压缩结果保留在会话历史，倒计时是估算值，不是 provider 的账单承诺。

关掉 tab 只关闭展示，不停止任务。用面板 Stop 停止后台成员。重启或第二设备连接后可以显式重新打开任务，公开历史继续可查；用户主动关闭的 tab 不会因后台事件反复弹出。

## 手机与离线首消息

Android 在线使用同一条任务会话、模型选择和任务面板。断网时只支持保存**新任务的首消息及附件**；本机 outbox 显示待发送、提交中、需处理等状态。恢复连接后自动创建 workspace 和任务会话并发送，使用原幂等键核对回执，避免重复建任务。查询失败时保留内容供重试。

已有任务的后续消息、模型选择、提示词和配置需要在线操作。旧手机看板副本、LWW 同步与旧积压不会导入。点到旧卡片通知时会显示「入口已停用」，请从项目的 workspace 进入新任务。冷启动尚未加载任务插件时首消息会等待加载或明确报错，不能静默变成普通会话。

## 设置与自动维护

侧栏保留「Agent 行为」「自动维护」「总 agent」「调度器」等设置入口，不再有「Vibe Board」或「会话汇总」看板入口。自动维护先创建任务会话和方案，仍需你显式确认执行。总 agent 只排序派发已确认任务，并在完成后整理记忆与需求文档。维护规则、提示词和配置仍按一份配置选择多个项目，不为各项目复制规则。

## 从旧版本升级

**旧卡片不迁移。** 旧卡、旧群聊、旧提案、旧事件和手机积压不变成新任务。升级会先对本机 `vibe.db` 做一致性备份并只读检查；备份失败就中止删除。成功后删除旧卡片及附属表、无消费者的旧同步表，保留项目扩展、预设及候选顺序、默认模型、提示词覆盖、维护规则及计数、记忆、统计，以及新 task/artifact/证据。

旧任务代码须已在相应 worktree 中保存；不要把旧卡当作代码备份。升级前记录仍需继续的旧任务及 worktree 路径，升级后在那个任务的独立 worktree 中建立新会话、说明已有改动和剩余目标，重新规划确认。不要让新任务在项目主检出执行。

日用安装的复核者按以下顺序升级：

1. 结束或停止仍运行的任务，保存旧任务 worktree 中的改动，关闭桌面窗口并执行安装目录的 `stop-daemon.ps1`。
2. 在已复核的源码上构建服务端、App/桌面与插件依赖，运行 `scripts/vibe/install-local.ps1`。脚本只复制文件，不替你删除数据；默认目标为日用安装目录，仅由复核者明确运行。
3. 按脚本输出安装或重载插件，启动新 daemon。首次打开共享数据库会自动先备份再迁移，不要手工提前 DROP 旧表。备份目录和迁移结果以启动日志为准。
4. 确认备份可读、项目配置等保留数据存在、侧栏没有旧入口，再新建一个任务走完验证和通过。手机也升级到对应新版。

新版读取旧布局，忽略不认识的布局字段，写回新增任务 tab 和关闭记录。降级到不认识任务会话的旧版时无法使用这些 tab；旧版可能忽略字段或丢弃其布局文件，所以升级前应保留 App 数据备份。数据库删除旧表后不要直接用旧插件启动，需由复核者决定从升级备份恢复的完整方案。
