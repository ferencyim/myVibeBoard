# myVibeBoard 需求总览（与底座无关的整理版）

> 2026-10-29 整理，供更换底座（Paseo → openbot 等）时逐条对照。来源：PRODUCT-REQUIREMENTS.md 第一至九轮及用户原话；已被后续轮次取代的设计（五栏看板、卡片、群聊容器等）不再列出。
> 编号格式 R-x.y，便于验收逐条打勾。第 9 节为第十轮新增。「当前」列为 Paseo 版现状：✅ 已实测可用 / ⚠️ 实现了但有缺口 / ❌ 未做到。

## 1. 定位与总原则

| 编号  | 需求                                                                                                                                              | 当前                    |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| R-1.1 | 个人 vibe coding 工作台：电脑上一个常驻服务统一驱动多种 agent CLI（Claude Code、Codex、Kimi、DeepSeek、OpenCode、qoder 等，不限于这些），按需启用 | ✅                      |
| R-1.2 | 客户端：桌面 + Android 手机（远程查看、回复提问、审批、离线写任务）；单用户；不做 iOS 客户端、多人协作、项目预算                                  | ⚠️ 手机端功能未全部实测 |
| R-1.3 | 连接：局域网/Tailscale 直连优先，自建端到端加密中继兜底（中继在用户的腾讯云主机，需与该机其它服务隔离）                                           | ✅                      |
| R-1.4 | 推送：vivo 官方推送（用户手机 vivo，无谷歌服务），FCM 可选                                                                                        | ⚠️                      |
| R-1.5 | （已删除，2026-10-29 用户确认：权限模式、「审批只能由用户做」都不是需求）                                                                         | —                       |

| R-1.9 | 设置入口要好找：各类设置直接出现在设置侧栏，不藏在二级菜单                                                                                        | ❌                      |

## 3. 任务与流程 tab（核心）

| 编号   | 需求                                                                                                                                                                                                    | 当前             |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| R-3.1  | 一个任务 = 一个独立 workspace/worktree；只有用户在新建界面建的才算任务                                                                                                                                  | ✅               |
| R-3.2  | 任务固定 6 个流程 tab：#1 主会话、#2 方案、#3 探路、#4 执行、#5 复核、#6 验证；编号任务内固定，标题「#n 角色 · 模型」；新建即全部显示（R-1.8）                                                          | ❌ 旧任务只有 #1 |
| R-3.3  | 未配置模型的角色沿用 #1 的模型；仅用户显式「不启用」#3/#5 才停用                                                                                                                                        | ✅ 新任务        |
| R-3.4  | tab 之间互相交流（核心）：任一 tab 能看其它 tab 记录、给它发消息、等它完成；按编号指代；对方在等审批时拒绝插话并提示用户去处理                                                                          | ✅               |
| R-3.5  | #1 = 群聊 + 时间线 + 群主：理解意图派给各 tab、跟进汇总；用户在 #1 用 `@#n` 或「发给」直接对某 tab 说话，权威等同在该 tab 说；各 tab 进展（结论、阶段、待审批、完成/失败）以状态行汇报到 #1，不耗 token | ✅               |
| R-3.6  | #2 方案支持 1~多个模型：第 1 个写，其余依次完整审阅（看得到前面的意见），写作模型汇总修订；只自动审初稿一次，再审用 `/重新审阅`；审阅者超时换候选                                                       | ✅               |
| R-3.7  | #3 探路共享：任一 tab 可请它调查，结论回给提问方                                                                                                                                                        | ✅               |
| R-3.8  | #4 执行：统一管理子代理与后台命令/终端；子代理派出前声明文件范围、范围重叠拒绝或串行、完成后比对越界告警；任务内共享任务板（认领、依赖）                                                                | ✅               |
| R-3.9  | 显式执行授权：/执行、面板「执行」、在 #4 直接说或 `@#4`；普通「认可/可以」不算；agent 互发的消息不算授权                                                                                                | ✅               |
| R-3.10 | 复核、验证：所有任务必须验证；验证 tab 可跑测试与构建，验证期间代码变化则本次验证作废                                                                                                                   | ✅               |
| R-3.11 | 换模型接手：新 tab `/接手 #n` 或「继续 #n 的工作」，带结构化交接包（检查点、改动文件、未决问题、下一步），每回合自动刷新，历史用围栏标为不可信数据                                                      | ✅               |
| R-3.12 | Git 收尾：用户点「通过」后自动安全合并到项目本地 main 并 push；冲突/脏树/代码变化即停止报告，绝不 force                                                                                                 | ✅               |
| R-3.13 | 任务间互相感知：同项目方案带状态（草稿/待确认/执行中/复核验证中/已完成/已放弃）与涉及文件；#2 写方案、#4 开工前必须查看，有重叠写明避让                                                                 | ✅               |
| R-3.14 | 轻量流程面板：阶段、各 tab 状态（点击切换）、每步结论、执行/通过/停止等按钮（与 slash 命令等价）；手机从菜单打开                                                                                        | ✅               |
| R-3.15 | 缓存到期倒计时：显示提示缓存到期时间，到期前可手动压缩，默认到期前自动压缩；缓存未过期时换模型提示多耗 token                                                                                            | ✅               |
| R-3.16 | 模型失败自动切换：额度耗尽、登录失效、不可用时按预设内模型顺序切换并记录，所有角色适用                                                                                                                  | ✅               |

## 10. 开发约束（对实现方）

- 公开仓库：不得提交密钥、主机地址、用户名、域名。
- 底座若为开源项目：每两周合并一次上游 release；自研功能尽量做成插件/扩展，底座改动单独提交、保持最小；保留上游许可声明。
- 执行者分工：设计、UI 挑错与复核由 Claude 做，具体编码/修复/调研交给 Codex CLI（gpt-6.1-sol、medium、正常速度）。
- 验收：每条需求在实际安装的应用里实测通过才算完成（R-1.8 类「界面完整」要求尤其要看界面）。
