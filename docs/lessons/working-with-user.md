# 与用户协作的场景和原话

规则在根 `AGENTS.md`，这里留原话和当时的场景，便于判断边界。

## 缺能力就改核心（2026-10-21）

插件功能受限于 Paseo 插件接口（如 agent 改名、Markdown 渲染器）时，曾报成已知限制。用户：“不是已经是fork的源码吗？这种情况就应该修改源码了”。简报和审核里把“宿主接口缺 X”当 `[core]` 任务（小、独立提交、协议向后兼容加能力门控）。

## 上游优先（2026-10-26）

用户：“每次更新代码之前，最好先拉取paseo的源仓库更新”。合上游是每轮的第一步。外部执行者运行时每 30 分钟核一次有无失控。

## 完整确认才算验收（2026-10-29）

用户：“我前面提的7点问题和要求，你要完整确认全部做到位了才可以验收啊，怎么总是没做完，没实现目标，就结束了？”；“不管有没有 agent 对话，UI 上应该始终是完整的”。事故细节见 [ops](ops.md)。

## 多排并行，不调优先级（2026-10-29）

用户：“不需要修改优先级，而是应该多多排并行任务，加快进度，不然你这样效率太低了”。瓶颈是审核和补测，执行者可以同时开多路；后台起多路时各挂一个等待以便收到完成通知。

## 模型按任务选（2026-10-29）

用户先要求“测试模型都用 luna”，随后改口：“忘掉 luna，你该用啥用啥，包括可以用 haiku5.5 和 sonnet5.5”。在意 token 消耗，但不想被单一模型绑死。实测不默认用最贵的模型。

## 别的会话的冻结不替用户做决定（2026-10-30）

别的会话为生产发布窗口请求“冻结本机重任务、不推送”，当时照做并暂停了本项目的构建和提交。用户：“本项目跟其它会话都没关系，为什么要等？”机器资源已由 guard 按实时负载放行。

## 描述现状不是需求（2026-11-01）

用户描述 bot 右侧面板 tab 只显示图标，被记进 PRODUCT-REQUIREMENTS.md 并实现成 `iconOnly` 模式。用户后来说这“从来不是需求”：只是描述情况，tab 本来就该像任务面板那样图标加文字。白加了代码和一条假需求，又要回退。不要从描述里发明模式或开关。
